# Stroika HH

Платформа поиска работы и подбора специалистов в строительной сфере.

## О проекте

Stroika HH — веб-платформа, предназначенная для взаимодействия работодателей и соискателей в строительной отрасли.

Основная задача проекта — упростить поиск вакансий, размещение предложений о работе, создание резюме и взаимодействие между компаниями и кандидатами.

## Основные ветки Git

| Ветка | Назначение |
|---|---|
| main | Стабильная версия проекта |
| develop | Основная ветка разработки |
| feature/* | Разработка новых функций |
| fix/* | Исправление ошибок |

### Правила работы с ветками

1. Запрещено вносить изменения напрямую в `main`.
2. Новые функции разрабатываются в отдельных ветках `feature/`.
3. Исправления выполняются в ветках `fix/`.
4. После завершения работы изменения отправляются через Pull Request в `develop`.
5. Ветка `main` обновляется только проверенными версиями проекта.

## Правила оформления коммитов

Используется формат:

`тип: краткое описание изменений`

Допустимые типы:

| Тип | Назначение |
|---|---|
| feat | Добавление функциональности |
| fix | Исправление ошибок |
| docs | Изменение документации |
| refactor | Рефакторинг кода |
| style | Изменение форматирования |
| test | Добавление или изменение тестов |
| chore | Изменение конфигурации и инфраструктуры |

Примеры:

```text
feat: add user registration
feat: implement vacancy search
fix: correct login validation
docs: update project documentation
refactor: improve vacancy service
test: add authentication tests
chore: configure development environment
```

## Правила Pull Request

Перед объединением изменений необходимо:

1. Создать Pull Request из рабочей ветки в `develop`.
2. Указать название и описание выполненной работы.
3. Проверить отсутствие конфликтов с целевой веткой.
4. Убедиться, что проверки качества кода и тесты проходят.
5. Получить подтверждение ответственного разработчика.
6. Выполнить Merge после проверки.

## Инструменты качества кода

Для поддержания единого стандарта разработки используются следующие инструменты.

### Backend (Python)

- **Ruff** — статический анализ и проверка ошибок.
- **Black** — автоматическое форматирование Python-кода.
- **pytest** — запуск автоматизированных тестов.

### Frontend (TypeScript / JavaScript)

- **ESLint** — поиск потенциальных ошибок и проблем в коде.
- **Prettier** — единый стиль форматирования.

### Автоматизация

- **GitHub Actions** — автоматический запуск проверок при отправке изменений и создании Pull Request.

Инструменты подключаются при инициализации соответствующих частей проекта.

- Соблюдать утверждённую архитектуру проекта.
- Использовать единый стиль написания кода.
- Не хранить пароли, токены и секретные ключи в репозитории.

- Документировать новые API и важные архитектурные изменения.
